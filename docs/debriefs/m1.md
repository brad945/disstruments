## What exists
- `backend/disstruments/ml/taxonomy.yaml` **v2.0.0**: 84 nodes / 64 leaves, 10 level-1
  families (guitar, bass, keys, drums, cymbals, percussion, strings, voice, brass,
  woodwinds). Every leaf declares real data sources or `planned: [synthetic|golden]`, and
  a test fails if a tag claims a source with zero real examples.
- `mappings.yaml`: every MedleyDB label, all 166 Slakh patches and all 20 OpenMIC classes
  mapped or explicitly ignored (tested against the real vocabularies).
- Loaders for MedleyDB, OpenMIC-2018 and Slakh2100, all built from their real format files
  (not from memory). All 330 real MedleyDB metadata files load with 0 unmapped labels.
- `python -m disstruments.ml.eval {taxonomy,baseline,run,compare,coverage,make-split}`. It
  reports mAP (macro, leaf, ≥3-positive leaves, micro), per-leaf and hierarchical F1 at 0.5
  and 0.6, and ECE (pooled, per-level and classwise) plus Brier. It also runs prior/random
  baselines and a promotion gate using a paired **artist-level** bootstrap.

## Decisions worth defending

**1. Partial labels are tri-state (positive / negative / unknown), never "absent = negative".**
When MedleyDB says "acoustic guitar", nylon vs steel is *unknown*, not negative. OpenMIC
ships an explicit `Y_mask`. Every metric takes the mask. *Interview Q: "Why not treat
unlabeled as negative?"* It turns coarse labels into false negatives for every fine leaf,
which punishes a model for being *more specific than the annotator*.

**2. Masking can itself bias metrics (the `percussion` bug).** v1 filed cymbals under
non-kit percussion and masked it on drum-kit tracks. `percussion` was then observed-negative
on exactly 1 of 123 drum tracks. A plain "is there a drum kit" score got **AP 0.94** on it,
which is label-dependent missingness in miniature. The fix was taxonomy 2.0.0 (cymbals at
level 1), plus an audit that compares observed-positive rate with overall rate per node, so
the next one gets caught. **Concept:** MNAR (missing-not-at-random) labels corrupt
evaluation silently. The evaluation needs the same scrutiny as the model.

**3. Raw-track labels may only *refine* the stem label.** MedleyDB stems list their raw mic
tracks. Adding those labels together put "clean electric guitar" (the DI track) inside every
distorted-guitar stem (15 cases) and put solo cello inside string sections. The rule is now
that a raw label counts only if it is a descendant of the stem's node; otherwise that node
is marked unknown.

**4. The split is a committed artifact, not a function call.** The greedy artist-disjoint
split changed depending on which files were loaded (330 metadata vs 196 with audio). 63
tracks moved, and 6 test tracks' artists appeared in train. `medleydb_split_v1.json` (196
public tracks, 136/31/29, stratified by genre and per-leaf positives) is now the default,
and loading fails loudly on mismatch or artist leakage.

**5. A promotion needs significance, not just a bigger number.** The test split has 29
tracks from 20 artists, and 16 of the 31 scoreable leaves have ≤2 positives. The gate
requires the same full config (threshold, bins, taxonomy/mappings/split hashes). It then
runs a paired bootstrap that resamples *artists*, requires the primary metric's 95% CI to
exclude 0, and applies per-metric tolerances (2% relative for mAP/F1, 0.005 absolute for
ECE/Brier).

## Baselines on the real MedleyDB test split (label-only; no audio needed)

| metric | prior | random |
|---|---|---|
| map_leaf (31 leaves) | 0.142 | 0.218 |
| map_leaf_min3 (15 leaves) | 0.234 | 0.303 |
| map_micro_leaf | 0.362 | 0.072 |
| hier_f1 | 0.343 | 0.267 |
| ECE (pooled) | 0.011 | 0.459 |

*Surprise worth explaining in an interview:* random beats the label prior on macro AP
(Δ +0.076, artist-bootstrap CI [0.065, 0.172]). A constant score's AP equals prevalence,
while random rankings have higher expected AP at small N. The gate still refuses random
because hierarchical F1 and calibration regress. That's the reason a gate needs more than
one metric, and why "beats baseline" needs a named baseline.

## Known limits (honest list)
- Only 35 of 64 leaves have *any* public MedleyDB positive; 15 have ≥3 test positives. Real
  eval covers under half the taxonomy until the golden set (§3.3) and Slakh arrive.
- `cymbals` on MedleyDB/Slakh is implied by a drum kit (100% agreement on test), so it
  duplicates kit detection. Never cite MedleyDB cymbal AP as cymbal-specific skill.
- Slakh has no reliable artist field, so it is dedup'd by MIDI (redux) but **never claim
  artist-disjoint**.
- MedleyDB is CC BY-NC-SA, so models trained on it are non-commercial (SYSTEMS_DESIGN §4.1).

## Open decisions for Bradley (defaults chosen; say the word to change)
1. **Drum kit ⇒ cymbals positive** on MedleyDB/Slakh (default). Alternative: score
   cymbals only on OpenMIC.
2. **Male/female singing collapsed to `voice.sung`.** A gendered label axis wasn't in the
   PRD, so the scope law applies. Restoring it needs an amendment (MedleyDB has ~50 of each).
3. **Screamed vocals, beatbox, sitar** have no public training source (`planned: [golden]`).
   Recommendation: keep screamed (rock-relevant; look at MoisesDB) and collapse sitar and
   beatbox.
4. **Picked vs fingered bass** are synthetic-only (no real data).
5. **Raw-label masking** also masks a few real instruments (e.g. drum set + tambourine,
   4 cases). It's conservative (unknown, never negative); allowing cross-family raw labels
   is a one-line change.
6. **Slakh near-silent floor −60 LUFS**: a chosen default.
