## Environment notes (things that cost time)
- **Network ≈ 250 KB/s** (measured 2026-10-07). Every GB of sample library is about an
  hour, so the source set is chosen to be small and timbre-diverse rather than complete.
  The Lakh clean-MIDI server (Columbia) ran ~30 KB/s.
- **sfizz has no Homebrew formula.** It's built from source (`sfizz_render` CLI) under
  `~/datasets/disstruments-synth/tools/sfizz`. Recent Apple Clang rejects a bundled
  header (`atomic_queue.h`: `-Wmissing-template-arg-list-after-template-kw` is an error by
  default now). Built with that warning downgraded, without patching the code:
  `-DCMAKE_CXX_FLAGS="-Wno-error=missing-template-arg-list-after-template-kw"`.
- **Surge XT / Dexed Homebrew casks** install system-wide pkgs (needs admin). Instead the
  sha256-verified dmg is unpacked and only the `.vst3` bundle is copied to
  `~/Library/Audio/Plug-Ins/VST3` (no sudo). pedalboard hosts it.
- **PANNs-style trap avoided:** pedalboard's `load_plugin` needs the VST3 bundle path;
  the paths are configurable (`DISS_SURGE_VST3`, `DISS_DEXED_VST3`, `DISS_SFIZZ_RENDER`).

## Design decisions (so far)

**1. Labels are perfect because the renderer, not the MIDI, decides the leaf.**
The MIDI track only provides a *role* (GM family / drum channel). The leaf is chosen
within the role, by a GM hint 70% of the time when the program is specific, otherwise by
the least-used leaf (class balance as a config knob). Parts with no v1 role are
**dropped, not rendered**, so nothing unlabelled is ever audible and every other taxonomy
node is a true negative. *Interview Q: "How do you know your synthetic labels are
right?"* — "They're right by construction: the only audio in a clip is stems we rendered
from leaves we chose. What *can* be wrong is the source → leaf mapping (a 'clean' sample
with drive), which is why every source is mapped explicitly and audited by ear."

**2. Effects may change production, never identity.** Per-leaf whitelists: distortion
only on the distorted-guitar leaf (and light grit on bass/keys), never on clean guitar
(a test checks 300 seeds). Chorus/phaser only on families that use them.

**3. Splits by composition, not clip.** Lakh's clean subset is `Artist/Title.N.mid`;
versions of a song share a key, and a stable hash of the key picks the split. The same
song never trains and tests. The composition is also the bootstrap group.

**4. Full recipe per clip, for later work.** `labels.json` stores:
- for each stem: source id + licence, engine meta (sfz/sf2 program/**full synth
  parameter dict**), velocity jitter, effects chain with params, LUFS, mix gain, MIDI
  track info;
- for the mix: master chain, target and actual LUFS, peak;
- the renderer git SHA and seed.

It's the "how was this sound made" ground truth from DIRECTION_NOTES.

**5. Licence flags are computed, not trusted.** A clip is `commercial_clean` only if
*every* source is clean **and** the MIDI is cleared. Lakh renders are therefore never
clean, whatever the sources. `sources.yaml` licences must be in a reviewed allowlist
(`sources.py`), and an NC licence can't be marked clean.

**6. The probe learns which backbone layer matters.** Softmax weights over all cached
layers + a linear head over every taxonomy node, masked BCE, early stopping on validation
macro AP. Bug caught by a test: at lr 1e-3 with small data the probe barely moved
(0.57 accuracy on a trivially separable problem). Linear models on standardized features
want lr ~1e-2.

## Render v1 (2026-10-07)
- **9,998 clips** (8,214 train / 892 val / 892 test), 10 s, 44.1 kHz mono FLAC, 16 GB.
  Took **29 min** on the M5 (7 workers, 0.145 s/clip); planning (parsing ~5k MIDI files)
  took 4.7 min. Splits are artist-disjoint (Lakh `Artist/` dirs).
- **Per-leaf counts** range from 737 (synth pluck/lead) to 3,790 (acoustic kit); cymbals
  is implied in 6,152 clips.
- **Sources:** 29 (1.0 GB of samples + 2 synths + our numpy 808). All 20 v1 leaves have
  a commercially clean source. FluidR3 GM is weighted 0.15 so one bank can't dominate.
- **306 stems were dropped as silent** (labels unaffected): 284 from one source (MTG tenor
  sax), whose key range the SFZ parser got wrong (see bug 5).

## War stories: label-noise bugs caught before training
1. **Silent stems labelled present.** The check was `any(|x| > 1e-5)`; near-silent
   renders passed, then quantized to zero in the 16-bit FLAC, giving a positive label on
   silence. Fix: require measurable LUFS and peak ≥ 1e-3 *after* effects.
   **Concept:** validate the artifact you train on, not an intermediate.
2. **Drum kit with its own key map.** The Muldjord kit ignores the GM drum map (kick =
   48, not 36), so 5 of 11 pilot kit stems were silent. Fix: per-source `note_map`.
3. **Audible but labelled absent.** Kits play hi-hats and cymbals, but `cymbals` is its
   own level-1 family, so with fully observed synthetic labels it was a *false negative*
   in every drum clip. Fix: hat/cymbal notes imply `cymbals`. Non-kit GM percussion
   (tambourine, cowbell, claps, congas) is dropped from kit parts, because those are
   other leaves. **Concept:** "fully observed" labels make every omission a false
   negative, so you must account for everything audible.
4. **GM fallback dominance.** Uniform choice among sources let one GM bank (17 leaves)
   win ~40% of stems in the pilot. Fix: per-source weights.
5. **Parsing SFZ is a trap.** Regions hide behind `#include` / `#define` /
   `default_path`; the MTG sax parsed as keys 39–40 (real 44–76), so octave fitting pushed
   phrases out of range. Fix: measure the playable range with a chromatic sweep render,
   cached per source. **Concept:** when a format has many dialects, measure behaviour
   instead of parsing structure.
6. **Synth patches leaking.** Surge renames parameters when the oscillator type changes,
   so restoring an init state by name failed. Fix: one plugin instance per leaf, and
   recipes that always set the same keys.

## Backbone integration notes
- **MERT-95M:** recent `transformers` returns no `hidden_states` for MERT's remote code.
  The 13 layer outputs are captured with forward hooks instead. 8 clips/1.3 s on MPS.
- **CLAP** (`laion/larger_clap_music`): `from_pretrained` stalled trying to fetch a
  safetensors conversion over the slow link. It loads from the local cache
  (`local_files_only`, `use_safetensors=False`). 6 pooled layers + the 512-d projection,
  8 clips/0.35 s.

## First baselines: synthetic test (2026-10-07)
Frozen backbone + linear probe, trained on synthetic train (8,214 mixes), early-stopped on
synthetic val, scored by the M1 harness on synthetic **test** (892 mixes, artist-disjoint
from train). 21 leaves scored (20 v1 leaves + implied `cymbals`).

| metric | prior | CLAP (Apache-2.0) | MERT-95M (CC-BY-NC) |
|---|---|---|---|
| map_leaf | 0.219 | 0.443 | **0.788** |
| map_macro (all nodes) | 0.293 | 0.520 | **0.821** |
| f1_micro_leaf @0.5 | 0.226 | 0.490 | **0.730** |
| hier_f1 | 0.453 | 0.597 | **0.782** |
| ECE (pooled) | 0.004 | 0.096 | 0.069 |
| openmic20_map (projection) | 0.420 | 0.654 | **0.854** |

**MERT − CLAP on map_leaf: +0.345, 95% CI [0.319, 0.360]** (paired bootstrap, 1,000
resamples over MIDI artists). This is the size of the music-specific-pretraining advantage
*on synthetic data*, and the main reason the licence-clean path needs M3 fine-tuning or
our own pretraining (A2) rather than shipping a frozen CLAP probe.

**Per-leaf, MERT:**
- **≥0.93:** bass families, drums, distorted guitar.
- **Weakest:** FM e-piano 0.49 and Rhodes 0.48, both rendered by the same Dexed FM engine
  (Rhodes is "FM-modelled"), so they're nearly indistinguishable by construction. This is
  the expected cost of D5, and the Rhodes leaf needs a real sampled source before its
  number means anything.
- **Also weak:** synth pluck 0.55, pad 0.65, organ 0.62.

**Layer weights:**
- **MERT:** fairly flat; the most weight is on layers 6, 10, 11 and the input projection.
- **CLAP:** splits between the first HTSAT stage (0.29) and the projected semantic
  embedding (0.25).

**Caveat:** these are synthetic-on-synthetic numbers. The domain gap to real recordings is
measured next (OpenMIC now, MedleyDB when access lands); expect a large drop.

## First real-music result: OpenMIC test (CLAP probe, trained on synthetic only)
OpenMIC split01 test (5,085 real clips, CC BY). One finding first: the official split is
**not perfectly artist-disjoint**. Artist `fma:15155` has 3 train clips and 1 test clip,
which the M1 leakage check caught. We never train on OpenMIC, so it's evaluated with the
check explicitly off and the leak recorded.

OpenMIC-20 per-class AP, split by whether the class is in our v1 training set:

| group | prior | CLAP probe (synthetic-trained) |
|---|---|---|
| **9 trained classes** (bass, cymbals, drums, guitar, organ, piano, sax, synth, trumpet) | 0.538 | **0.644** |
| 11 untrained classes (violin, flute, banjo, …) | 0.372 | 0.316 |
| all 20 (openmic20_map) | 0.447 | 0.464 |

- **Synthetic → real transfer works.** Drums +0.15, guitar +0.18, piano +0.13,
  cymbals +0.15 (the implied-cymbals labels paid off), bass +0.13, organ +0.11,
  trumpet +0.09.
- **Two classes don't move.** Synthesizer 0.706 = prior and sax +0.02. The renderer's
  synths are only our own simple Surge patches, and the sax sources are thin (one real
  recording set; MTG mostly silent).
- **Domain gap (CLAP):** on the same 9 classes the synthetic-test projection is far
  higher (openmic20 on synthetic test 0.654 over all classes present), so there is a
  large gap to close. That gap is M4's job.
- **The headline 20-class number hides all of this.** Untrained classes drag it down to
  ~prior, so always report the trained/untrained split.
