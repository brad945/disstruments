## Environment notes (things that cost time)
- **Network ≈ 250 KB/s** (measured 2026-10-07). Every GB of sample library is about an
  hour, so the source set is chosen to be small and timbre-diverse rather than complete.
  The Lakh clean-MIDI server (Columbia) ran ~30 KB/s.
- **sfizz has no Homebrew formula.** It's built from source (`sfizz_render` CLI) under
  `~/datasets/disstruments-synth/tools/sfizz`. Recent Apple Clang rejects a bundled
  header (`atomic_queue.h`: `-Wmissing-template-arg-list-after-template-kw` is an error by
  default now). Built with that warning downgraded, without patching the code:
  `-DCMAKE_CXX_FLAGS="-Wno-error=missing-template-arg-list-after-template-kw"`.
- **Surge XT / Dexed Homebrew casks** install system-wide pkgs (needs admin). Instead the
  sha256-verified dmg is unpacked and only the `.vst3` bundle is copied to
  `~/Library/Audio/Plug-Ins/VST3` (no sudo). pedalboard hosts it.
- **PANNs-style trap avoided:** pedalboard's `load_plugin` needs the VST3 bundle path;
  the paths are configurable (`DISS_SURGE_VST3`, `DISS_DEXED_VST3`, `DISS_SFIZZ_RENDER`).

## Design decisions (so far)

**1. Labels are perfect because the renderer, not the MIDI, decides the leaf.**
The MIDI track only provides a *role* (GM family / drum channel). The leaf is chosen
within the role, by a GM hint 70% of the time when the program is specific, otherwise by
the least-used leaf (class balance as a config knob). Parts with no v1 role are
**dropped, not rendered**, so nothing unlabelled is ever audible and every other taxonomy
node is a true negative. *Interview Q: "How do you know your synthetic labels are
right?"* — "They're right by construction: the only audio in a clip is stems we rendered
from leaves we chose. What *can* be wrong is the source → leaf mapping (a 'clean' sample
with drive), which is why every source is mapped explicitly and audited by ear."

**2. Effects may change production, never identity.** Per-leaf whitelists: distortion
only on the distorted-guitar leaf (and light grit on bass/keys), never on clean guitar
(a test checks 300 seeds). Chorus/phaser only on families that use them.

**3. Splits by composition, not clip.** Lakh's clean subset is `Artist/Title.N.mid`;
versions of a song share a key, and a stable hash of the key picks the split. The same
song never trains and tests. The composition is also the bootstrap group.

**4. Full recipe per clip, for later work.** `labels.json` stores:
- for each stem: source id + licence, engine meta (sfz/sf2 program/**full synth
  parameter dict**), velocity jitter, effects chain with params, LUFS, mix gain, MIDI
  track info;
- for the mix: master chain, target and actual LUFS, peak;
- the renderer git SHA and seed.

It's the "how was this sound made" ground truth from DIRECTION_NOTES.

**5. Licence flags are computed, not trusted.** A clip is `commercial_clean` only if
*every* source is clean **and** the MIDI is cleared. Lakh renders are therefore never
clean, whatever the sources. `sources.yaml` licences must be in a reviewed allowlist
(`sources.py`), and an NC licence can't be marked clean.

**6. The probe learns which backbone layer matters.** Softmax weights over all cached
layers + a linear head over every taxonomy node, masked BCE, early stopping on validation
macro AP. Bug caught by a test: at lr 1e-3 with small data the probe barely moved
(0.57 accuracy on a trivially separable problem). Linear models on standardized features
want lr ~1e-2.
